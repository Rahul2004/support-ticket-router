[1:00 — ARCHITECTURE]
(show assets/architecture_diagram.png)
Let's walk through the architecture diagram to see how it works.
First, the workflow starts and enters the security checkpoint node, which redacts emails or phones and scans for prompt injection.
If a security threat is found, it routes to the security failure handler and blocks execution.
If clean, it routes to the orchestrator agent, which coordinates the classification and response drafting.
The orchestrator delegates work to the ticket_classifier agent to analyze category and sentiment, and the response_drafter agent to write a reply.
Both sub-agents use our stdio MCP server to access ticket history, customer tiers, and knowledge base articles.
Next, the draft response goes to the human review node, where it pauses for human approval.
Finally, once approved, the workflow sends the clean output and logs the security audit history.
